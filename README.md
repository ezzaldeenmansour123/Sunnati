# سُنَّتي | SUNNATI

**السنة النبوية بين يديك، بفهم موثّق وذكاء متقدم.**

مكتبة حديثية عربية تعمل دون إنترنت — الكتب التسعة كاملة — مع بحث متقدم،
ومساعد استرجاع محلي، وتراجم رواة، وتخريج، وشروح. مجاني، بلا إعلانات،
بلا حسابات. Flutter + Dart + SQLite/FTS5.

> **الحالة بصراحة (v1.0.0 — المراحل 9 و10، 2026-11-26):** الكتب التسعة
> مثبّتة وموثّقة داخل التطبيق: **65,712 حديثاً** (البخاري 7,580، مسلم
> 7,360، أبو داود 5,272، الترمذي 3,924، النسائي 5,679، ابن ماجه 4,338،
> أحمد 26,363، مالك 1,829، الدارمي 3,367) + **3,574 شرحاً** من موسوعة
> الأحاديث النبوية (HadeethEnc) + **67,334 حكماً** منسوباً إلى أصحابه
> (20,998 حديثاً لها درجات، مع إبقاء الأقوال المتعارضة كلها دون اختيار
> «درجة رسمية» واحدة). قاعدة البيانات سليمة (`quick_check` و
> `integrity_check` = ok) وتُتحقق من SHA-256 عند أول تشغيل.
>
> **ما ليس موجوداً بعد — بصراحة كاملة:** تراجم الرواة (جدول `narrators`
> فارغ — 0 ترجمة موثقة)، والطرق والتخريج والمقارنات بين الروايات
> (الجداول فارغة)، والبحث الدلالي (بالمعنى)، ومدير التنزيلات
> (الاستكمال/التحديث الجزئي)، ولوحة الإدارة. الشاشات الخاصة بها موجودة
> وتقول ذلك صراحة بدل اختراع بيانات. الضغط على اسم راوٍ داخل نص الحديث
> يعمل كآلية (محلل إسناد + نص قابل للضغط + بطاقة الراوي) لكنه **لا يربط
> أي اسم فعلياً** ما دام جدول الرواة فارغاً — الربط يحتاج مصدر رواة
> موثوقاً ومرخّصاً (الخطة في
> `SUNNATI_PHASE5_CORE_PLAN_2026-11-26.md` في مستودع التقارير، وتنتظر
> موافقة المالك قبل أي تنفيذ).
>
> **ما لم يُختبر محلياً بعد:** `flutter analyze` و`flutter test` وبناء
> APK — لا توجد بيئة Flutter في جهاز التحقق؛ تُنفَّذ في GitHub Actions
> عند أول رفع (انظر `.github/workflows/build.yml`). لا تُعلن أي مرحلة
> مكتملة إلا بملفات فعلية واختبارات ناجحة وسجل موثق.
>
> **ملاحظة عن التزامن:** أثناء عمل المرحلتين 9 و10 (2026-11-26 02:07–02:40)
> كانت ملفات المراحل 4 و6 و7 و8 تصل إلى الشجرة من فرق موازية؛ هذا
> التقرير يوثق حالة الشجرة كما قيسَت فعلياً في نهايته، وقائمة الرفع
> أُعيد توليدها في النهاية لتلتقط آخر الملفات.

## الهوية البصرية (مصححة بقرار المالك 2026-11-25)

هوية مستقلة فاخرة — **بلا أخضر زمردي وبلا أخضر ديني كلون رئيسي إطلاقاً**:

| الدور | اللون | Hex |
|---|---|---|
| خلفيات | عاجي دافئ | `#F7F2E9` / `#FAF6EC` |
| رئيسي وعناوين | أزرق بترولي عميق | `#0F3B4D` / `#143C4B` |
| نصوص ثانوية ومحايد | رمادي بنفسجي هادئ | `#6E6A7A` / `#8A8494` |
| تفاصيل محدودة | ذهبي مطفي (غير لامع) | `#B89B5E` / `#C2A265` |
| لمسات ضئيلة فقط | وردي باهت | `#E8CFC8` |

الواجهة حديثة بسيطة راقية واضحة، بعيدة عن الزخارف المبالغ فيها أو
القوالب التقليدية للتطبيقات الإسلامية. روح التصميم المرجعي محفوظة
(شعار الكتاب المفتوح والقبة، والشاشات الـ15) بهذه اللوحة الجديدة.
الألوان مصدرها الوحيد `lib/core/theme.dart`؛ الأيقونة تُولد من
`tools/make_icon.py` (بترولي وذهبي مطفي على عاجي — بلا أخضر إطلاقاً)،
ومصدرها `tools/icon-source.png` (أيقونة 2026-11-26 v2).

## البنية

```
lib/
  main.dart            # نحيف: تهيئة + MaterialApp فقط
  core/                # theme.dart (الهوية)، normalize.dart (تطبيع عربي)، app_version.dart
  models/              # book, hadith, narrator, grade, chain, takhrij, user_data
  data/                # database.dart (SQLite + SHA-256 + quick_check)، user_repository.dart
  search/              # search_service.dart (FTS5: كلمة/جملة/رقم/كتاب/درجة)
  assistant/           # assistant_service.dart (استرجاع محلي فقط — لا توليد)، narrator_assistant.dart
  ui/                  # 12 شاشة: home, library, book, hadith_reader, search,
                       #   assistant, narrators, takhrij, commentaries,
                       #   downloads, favorites, settings (+ widgets)
test/                  # 6 ملفات، 47 اختباراً — CI يفشل عند فشل أي منها
tools/                 # build_db.py (بناء DB)، isnad_parser.py (+ اختباراته)، make_icon.py
android/               # مشروع Android كامل في المستودع — applicationId ثابت com.sunnati.app
.github/workflows/     # build.yml — analyze + test + build DB + font + icon + signing + APK + Release
                       # generate-keystore.yml — توليد keystore الإصدار مرة واحدة (يدوي)
```

دروس عز السنة المطبقة هنا: لا ملف `main.dart` واحد ضخم، `android/`
موجود في المستودع (لا توليد في CI)، التوقيع يُقرأ من keystore خارج
المستودع مع تحذير صريح عند غيابه (لا debug صامتاً في إصدار يُسلَّم)،
`test/` موجود ولا يُحذف أبداً، رقم الإصدار من مصدر واحد
(`lib/core/app_version.dart` مطابق لـ `pubspec.yaml` ويفحصه CI).

التفصيل الكامل في [`SOURCES.md`](SOURCES.md) وفي صفحة «المصادر
والتراخيص» داخل التطبيق (الإعدادات → المصادر والتراخيص).

الأبواب للكتب السبعة إنجليزية كما وردت في المصدر (لا عنوان عربي موثق
بعد)، و720 صفاً برقم باب 0 تحت باب «غير مصنّف» صراحة. 76 حديثاً تحوي
محرف الاستبدال U+FFFD مستوردة مع وسم `has_encoding_issue=1` لا محذوفة
ولا «مصلحة» بالتخمين.

## البناء

```bash
flutter pub get
flutter analyze
flutter test
python3 tools/build_db.py --out assets/sunnati.db   # ينزّل parquet الناقص من Hugging Face ويثبّت SHA-256
flutter build apk --release --target-platform android-arm64
```

التوقيع: ضع keystore خارج المستودع وأنشئ `android/key.properties`:

```properties
storePassword=...
keyPassword=...
keyAlias=...
storeFile=keystore.jks
```

في CI تُمرر الأسرار `KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` /
`KEY_ALIAS` / `KEY_PASSWORD`. بدونها يبني CI بتوقيع debug مع تحذير
واضح في السجل — ولا يُوزَّع ذلك البناء كإصدار، بل يفشل بناء أي وسم
إصدار (tag) بلا keystore. لتوليد keystore الإصدار مرة واحدة انظر
`.github/workflows/generate-keystore.yml` والتعليمات في
[`SIGNING.md`](SIGNING.md) — **لا يُوضع أي مفتاح خاص داخل المستودع
أبداً**، وفقدان المفتاح يعني فقدان هوية التوقيع واضطرار المستخدمين
لإعادة التثبيت.

الأيقونة: `python3 tools/make_icon.py --out android/app/src/main/res`
(يتطلب Pillow).

## حالة المراحل

| المرحلة | الحالة |
|---|---|
| 1 — مشروع وبنية وتصميم | مكتملة — الملفات والشاشات الـ12 والاختبارات موجودة |
| 2 — قاعدة بيانات واستيراد | مكتملة — 65,712 حديثاً + 3,574 شرحاً، سليمة وموثقة |
| 3 — الكتب التسعة والتحقق | مكتملة — العدّ والمصادر والدرجات والتطبيع موثقة (عناوين الأبواب العربية ما زالت معلّقة) |
| 4 — محرك البحث | جزئي — بحث نصي FTS5 + تطبيع عربي + تشكيل محفوظ يعمل (موثق بأرقام في تقرير المرحلتين 9 و10). باني فهارس المرحلة 4 (`tools/phase4_search_index.py`: تقسيم سند/متن، بحث في الشروح، مرادفات وجذور) جُرِّب فعلياً على نسخة عمل ونجح (65,712 صفاً، 69.8 ثانية) **لكنه ليس في قاعدة البيانات المسلَّمة ولا في CI ولا مربوطاً في بحث Dart** — وتكلفته +153 ميجابايت (القاعدة 326 ميجابايت) فيرفع APK إلى ~330 ميجابايت، فيلزم قرار المالك قبل تفعيله. البحث الدلالي بالمعنى (embeddings) غير منفَّذ — البديل الحالي معجمي (جذور + مرادفات) |
| 5 — شروح وتخريج ورواة | جزئي — الشروح موجودة (3,574)؛ الرواة والتخريج والطرق بلا بيانات موثقة (0 صفوف)، والربط الفعلي للأسماء داخل النص غير مفعّل (الآلية موجودة: محلل إسناد + نص قابل للضغط + بطاقة الراوي) |
| 6 — SUNNATI AI وRAG | جزئي — محرك استرجاع بايثون موثق (`tools/assistant_engine.py` + 5,203 صياغة أسئلة في 15 فئة): اختبار 57 سؤالاً أُعيد تشغيله في المرحلة 9 فنجح **46/57** وصفر اختلاق (الاستشهادات حقيقية والنصوص حرفية) — 11 فشلاً موثقة في التقرير. مساعد Dart داخل التطبيق استرجاع FTS فقط، وملف الصياغات (`assets/assistant_phrasings.json`) **غير مضمّن في `pubspec.yaml`** فلا يصل للتطبيق — يلزم ربطه أو حذفه بقرار موثق. لا توليد ولا RAG/نموذج |
| 7 — تنزيل ودون إنترنت | جزئي — دون إنترنت يعمل (المكتبة مضمّنة، بلا إذن إنترنت)؛ مدير التنزيلات منفَّذ كاملاً (تنزيل + استكمال + إيقاف/استئناف + تحقق SHA-256 متدفق + حذف) ومربوط في شاشة التنزيلات، **لكن بلا أي حزمة**: سجل الحزم فارغ (0) والمكتبة الموسعة كلها «قيد التجهيز» بلا روابط أو أحجام — فلا تنزيل حقيقي ممكن حتى تُبنى أول حزمة موثقة |
| 8 — لوحة إدارة | جزئي — الخلفية موجودة (مخطط v4: staging + audit + PIN مشفر SHA-256 مع قفل بعد 5 محاولات + مستودع إدارة) وتُنشأ عند أول تشغيل، **لكن بلا أي وصول من الواجهة**: شاشة القفل موجودة ولا يصل إليها أي زر أو مسار في التطبيق |
| 9 — اختبارات شاملة | مكتملة محلياً قدر الإمكان — انظر `SUNNATI_PHASE9_10_REPORT_2026-11-26.md` (22 اختباراً: ناجح/فاشل/غير منفَّذ بأرقام حقيقية)؛ Dart + بناء APK في CI |
| 10 — APK النهائي | CI ينشر `v1.0.0-build-N` (arm64-v8a)؛ الإصدار المستقر `v1.0.0` يُوسم بعد نجاح أول تشغيل لـ CI |

## قواعد لا تُكسر

- لا حديث وهمي أو تجريبي إطلاقاً؛ النص المخزَّن يُحفظ بتشكيله، والتطبيع نسخة فهرسة مستقلة.
- لا حكم/سند/ترجمة/شرح منسوب دون مصدر؛ ولا قسم يُعرض مكتملاً بلا بيانات.
- المساعد يسترجع فقط — لا توليد، لا فتوى، لا ادعاء ذكاء اصطناعي بلا عمل.
- لا زر بلا وظيفة: ما لا يعمل بعد يُخفى لا يُعرض معطلاً وهمياً.
- لا مفاتيح أو keystore داخل المستودع أو APK.
