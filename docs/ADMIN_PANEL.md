# لوحة إدارة SUNNATI — الدليل والأمان

> **الحالة:** المرحلة 8. اللوحة منفصلة عن واجهة المستخدم العادية
> وتُفتح من الإعدادات ← «لوحة الإدارة» فقط.

## الحماية (رمز الدخول)

- **لا رمز افتراضي** في أي مكان من الكود. عند أول فتح للوحة يضبط
  المالك رمزاً (4–12 رقماً).
- الرمز **لا يُحفظ نصاً أبداً**: يُخزَّن في SharedPreferences فقط
  بصيغة `v1$iterations$saltHex$hashHex` حيث الهاش SHA-256 مكرر
  10,000 مرة على (الملح + الرمز)، والملح 16 بايت عشوائي جديد لكل
  رمز. التحقق بمقارنة ثابتة الزمن.
- الرمز الضعيف يُرفض عند الضبط: رقم واحد مكرر (`0000`) أو أرقام
  متتابعة (`1234`، `4321`).
- **القفل:** 5 محاولات خاطئة متتالية تقفل اللوحة 5 دقائق. النجاح
  يصفّر العداد.
- تغيير الرمز يتطلب الرمز الحالي، ويُسجَّل في سجل التدقيق
  (`pin_changed`).
- لا مفاتيح API ولا أسرار داخل APK إطلاقاً — اللوحة محلية بالكامل.

## الوظائف

| التبويب | ما يفعله | ما لا يفعله |
|---|---|---|
| نظرة عامة | عدادات: قيد المراجعة / معتمدة / مرفوضة / التدقيق / الحزم / الرواة / الأحاديث | — |
| المراجعة | اعتماد/رفض سجل مرحلي مع ملاحظة (الرفض يحتاج سبباً) | لا ينشر محتوى في المكتبة |
| استيراد | لصق JSON/CSV → تحقق → حفظ «قيد المراجعة»؛ تعريف كتاب (وصف فقط) | لا يقبل ملفاً فاشلاً أبداً |
| الجودة | كشف تكرار، فحص نواقص، إعادة فهرسة FTS5 | — |
| الحزم | عرض الحزم المعروفة + إعادة إصدار بيانها (نسخ) | إصدار حزمة جديدة يتم بأداة سطح المكتب فقط |
| سجل التدقيق | عرض صفحي (20 صفاً) للسجل — قراءة فقط | لا تعديل ولا حذف |
| الإعدادات | تغيير الرمز، تصدير/استعادة نسخة احتياطية لبيانات المستخدم | النسخة لا تشمل المكتبة ولا التدقيق |

## قاعدة المراجعة (ملزمة)

1. كل إدخال يُحفظ `pending_review` أولاً.
2. الاعتماد لا ينشر محتوى حديثياً/رجالياً في جداول المكتبة من
   اللوحة: دمج الشروح والتراجم والأحكام المعتمدة في جداول الإنتاج
   يتم عبر **خط الاستيراد الموثّق (المرحلة 9)** وليس من اللوحة.
3. الاستثناء الوحيد: **تعريف كتاب** — عند اعتماد تعريف كتاب تُدرج
   صفته فقط في جدول `books` بعدد `cnt=0` («قيد الاستيراد»)، بلا أي
   محتوى حديثي.
4. كل إجراء (استيراد، اعتماد، رفض، تعريف، فهرسة، حزمة، رمز، نسخة
   احتياطية) يكتب صفاً في `admin_audit_log` (الفاعل/الإجراء/
   الكيان/المصدر/التفاصيل/الوقت). السجل إلحاقي: لا يوجد في التطبيق
   أي مسار لتعديله أو حذفه.

## التحقق من ملفات الاستيراد

- الحجم ≤ 10 MiB، السجلات ≤ 10,000، الحقل الواحد ≤ 200,000 حرف.
- JSON: كائن فيه `kind` + `records` فقط. CSV: صف ترويسة بأعمدة
  النوع المسموحة تماماً.
- الأنواع: `book` (معرف/اسم/مؤلف/مصدر/ترخيص)، `commentary`
  (مفتاح حديث/نص/مصدر)، `narrator` (اسم/مصدر)، `grade`
  (مفتاح حديث/مصحح/حكم/مصدر)، `source` (اسم/ترخيص).
- كل سجل بلا `source` يُرفض. حكم راوٍ بلا `status_src` يُرفض.
- حقول غير معروفة تُرفض (خطأ إملائي لا يصبح عموداً صامتاً).
- المعرفات صارمة: معرف كتاب `^[a-z0-9][a-z0-9_-]{0,63}$`، مفتاح
  حديث `^[a-z0-9_]+:\d+$`.
- تكرار الهوية داخل ملف واحد يُرفض (بمقارنة التطبيع العربي).
- محتوى مشبوه يُرفض ولا يُنفَّذ ولا يُخزَّن خاماً: بايت NUL،
  مسارات (`..`، `/` بادئة، حرف محرك، `\`)، شظايا أوامر
  (`$(`، `` ` ``، `${`)، أسطر جديدة في حقول المعرفات، وخلايا CSV
  تبدأ بـ `=` أو `+` أو `-` أو `@` (حقن صيغ جداول).
- التحقق قراءة فقط: لا يمس جداول الإنتاج ولا يشغّل أي شيء من الملف.

## النسخ الاحتياطي والاستعادة

- التصدير: JSON بيانات المستخدم (مفضلة/وسوم/ملاحظات/سجل قراءة)
  يُنسخ إلى الحافظة ويُسجَّل في التدقيق.
- الاستعادة: تُفحص قبل الاستبدال — حد 1 MiB + صيغة
  `sunnati-user-data`؛ الفشل يترك البيانات الحالية دون مساس.

## المخطط (v4)

- `admin_staging`: السجلات المرحلية مع `payload_json` و`sha256`
  و`review_status` وحقول المراجعة.
- `admin_audit_log`: سجل التدقيق الإلحاقي.
- `downloaded_libraries` + 7 أعمدة v4 (مصدر/ترخيص/رابط/أحجام/
  بيان/تحديث). تُنشأ عند فتح التطبيق (خامل على قاعدة v2/v3) وفي
  البناء الجديد عبر `tools/build_db.py` (SCHEMA_V4) والترحيل عبر
  `tools/migrate_schema_v4.py` (على نسخة عمل فقط — لا تُلمس
  `assets/sunnati.db` مباشرة).
